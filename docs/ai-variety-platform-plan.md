# AI 微综艺 · 横屏 5–10 分钟成片平台 · 技术方案 v0.1
> 目标：做一个「选模式 → 写台本 → 管资产 → 出分镜 → 批量生成 → 包装成片」的平台。单集 5–10 分钟，横屏 16:9，成片 1080P，生成侧走你现有的 ComfyUI + MiniMax H3（768P 即可）。
> 界面与交互逻辑参考 ArcReel（项目制 + 资产先行 + 分镜/生成工作区 + 费用追踪 + 版本回滚），但**只借鉴交互，不复制其代码**（ArcReel 是 AGPL-3.0，直接改代码做闭源 SaaS 有传染风险）。
> 产品品类：**AI 微综艺**（横屏 5–10 分钟/集）· 品牌名：待定（候选见下）
> 版本：2026-10-23 · 状态：待评审

## 0. 一页结论（TL;DR）

| 问题 | 结论 |
|---|---|
| 做不做平台 | 做，但**平台只做编排、资产、时间线、包装**，生成全部外置到 ComfyUI/云 API |
| 硬件 | 平台本身**不需要 GPU**（普通服务器/笔记本即可）；渲染靠你的 ComfyUI 节点 |
| 生成 | MiniMax H3 via ComfyUI，768P，默认 5 秒/镜头，长镜头 8–10 秒；横屏 1280×720 生成 → 1080P 交付 |
| 单集规模 | 6–8 分钟 ≈ 70–100 个镜头 ≈ 80–120 次生成任务（含重试） |
| 单集成本 | H3 768P 行情约 0.08–0.09 元/秒 → **全生成约 ¥35–55/集**，含重试 ¥50–90/集；TTS/LLM 仅几元 |
| 周期 | 3–4 人，P0 验证 1–2 周；8–10 周出第一集 6–8 分钟成片；12 周产品化 |
| 最大风险 | ① H3 可用性/并发/商用条款；② 口型与多人物同框；③ 横屏长视频的分发与节奏 |

**一句话打法**：用「固定节目模式 + 资产锁定 + 分段生成 + 模板包装」把不确定性关进笼子，先让 1 个模式稳定出 6–8 分钟成片，再扩模式、扩集数。

## 1. 目标与硬约束

### 1.1 目标
- 输入：一个选题/一段台本 + 一套节目模式；
- 输出：**单集 5–10 分钟、横屏 16:9、1080P、带主持/嘉宾/字幕/花字/音效/BGM/片头片尾的完整成片（MP4）**，可选导出剪映草稿继续精修；
- 可批量：同一模式换选题即可复制生产，单集返工控制在 20% 以内。

### 1.2 约束（已确认 + 假设）
| 项 | 现状 | 对方案的影响 |
|---|---|---|
| 画幅 | 横屏 16:9 | 生成 1280×720（768P）→ 交付 1920×1080；UI 时间线按 16:9 预览 |
| 时长 | 5–10 分钟/集 | 必须做「分幕 + 分镜 + 多轨时间线」，不能靠单次生成 |
| 显卡 | 无 24G 显卡 | 平台不做本地推理；渲染全部走 ComfyUI（远程/局域网/云）或云 API |
| 生成 | ComfyUI 里已有可用的 MiniMax H3 | 以 H3 为主 provider，做可替换适配层；768P 可接受 |
| UI | 认可 ArcReel 的界面与逻辑 | 项目制、资产先行、分镜卡片、生成工作区、任务中心、费用追踪、版本回滚 |
| 团队 | 待定（建议 3–4 人） | 一人前端、一人后端、一人 AI 落地（ComfyUI/prompt）、兼职剪辑/设计 |

## 2. 产品定位与 MVP 边界

### 2.1 定位
**「节目模式驱动的 AI 成片生产平台」**：不是通用视频编辑器，也不是模型聚合器，而是把「一种节目怎么做」固化成可执行流水线。

横向可扩展三种内容形态，共用同一套引擎：
| 内容形态 | 模式层 | 镜头层 | 成片特征 |
|---|---|---|---|
| **AI 综艺（MVP 首选）** | 节目模式 DSL（段落/赛制/花字/音效） | 主持+嘉宾、正反打、反应镜头、空镜 | 5–10 分钟横屏，包装重 |
| AI 短剧 | 剧集结构（分集/分场/对白） | 角色/场景、正反打、特写 | 5–10 分钟横屏/竖屏 |
| AI 漫剧 | 分镜图 + 轻运镜 | 关键帧、I2V、少量运镜 | 3–8 分钟，画风一致性优先 |

> 本方案以「AI 综艺」为 MVP 模式，但下面所有模块都按「模式可插拔」设计，后面加短剧/漫剧只加模板与规则，不改内核。

### 2.2 MVP（v0.1）范围
**只做一个节目模式：横屏 AI 圆桌/访谈综艺（6–8 分钟/集）**
- 固定虚拟棚（2–3 个机位：中景双人、单人特写、全景）；
- 1 主持 + 2 嘉宾（AI 形象 + 固定声线 + 固定人设/口癖）；
- 段落结构：片头 → 开场 → 嘉宾介绍 → 话题 1 → 话题 2/小游戏 → 结尾 + 下期预告；
- 镜头类型：说话镜头（正反打）、反应镜头、空镜/环境、花字卡、片头片尾；
- 交付：MP4 1080P + 字幕（硬字幕/软字幕可选）+ 剪映草稿（可选）。

**v0.1 明确不做**：多集连续剧、多人实时互动、直播、复杂运镜、口型精修（先用切镜/反应镜头规避）、多语言配音、移动端。

### 2.3 为什么 MVP 选「访谈/圆桌」
- 生成难度最低：以固定机位说话镜头 + 反应镜头 + 空镜为主，规避「多人同框 + 复杂动作 + 长镜头」；
- H3 5 秒镜头天然适配正反打剪辑；
- 综艺感主要靠台本冲突 + 花字音效包装，不靠画面奇观；
- 模式可复制：换选题就是新一期，便于验证「批量出片」这个核心价值。

## 3. 设计原则

1. **资产先行（ArcReel 逻辑）**：先把主持/嘉宾/场景/道具/风格锁死，再生成镜头；没有资产不允许进分镜。
2. **平台轻、渲染重**：编排、存储、时间线、包装跑在普通服务器；ComfyUI/云 API 负责生成，用 adapter 隔离。
3. **分段生成，不赌整片**：5–10 分钟拆成 6–8 个段落、70–100 个镜头，逐镜头生成 + 质检 + 替换，任一镜头失败不影响整集。
4. **模板包装是护城河**：片头、花字、音效、转场、调色、字幕样式全部模板化，这是「像综艺」的关键，也是复用的关键。
5. **一切可回滚**：每次生成保留版本（提示词/参考图/参数/输出），成片时间线可回滚到任意版本。
6. **成本可见**：每个任务记录 provider/时长/单价/费用，项目级预算告警。
7. **合规内置**：AI 生成标识、字体/音乐/音效授权清单、肖像/声音使用边界写进流程。

### 5.1 全局布局

```
│ ▸ 素材库 │  主工作区（卡片/表格/宫格/时间线）                       │
│ ▸ 任务   │                                                         │
│ ▸ 设置   │                                                         │
└────────┴─────────────────────────────────────────────────────────┘
```

### 5.2 五步创作流（核心交互）

**① 剧本**
- 选节目模式（模板卡片）→ 填选题/关键词 → LLM 生成台本；
- 台本按「段落/说话人/台词/动作/情绪」结构化展示，支持逐段重写、锁定段落、导出；
- 一键「生成分镜」：把台本拆成镜头草案（镜号/时长/景别/机位/说话人/台词/画面描述）。

**② 资产**
- 主持/嘉宾卡：正面/侧面/表情参考图（多图）、声音 ID、人设（口癖/关系/禁忌话题）、服装；
- 场景卡：虚拟棚机位图、空镜、背景板；道具/风格卡（LUT、字体、花字配色）；
- 支持从历史项目复用资产；**资产未就绪时，分镜页显示阻塞提示**。

**③ 分镜**
- 双视图：**表格视图**（镜号/时长/景别/机位/角色/台词/首帧/尾帧/状态）与 **宫格视图**（缩略图墙，ArcReel 式）；
- 镜头卡片状态：草稿 / 待生成 / 生成中 / 已生成待选 / 已选定 / 需重生成；
- 批量操作：批量生成、批量重写提示词、批量换参考图、按段落重排、插入空镜/花字卡。

**④ 生成**
- 选模型与参数（H3 768P / 5s / 横屏 / 首帧或参考图模式）；
- 提交后进入任务队列：进度、耗时、费用、失败原因；支持重试、取消、优先级；
- 每个镜头保留多版本（version 1..n），并排预览、一键选用；写回分镜。

**⑤ 成片**
- 多轨时间线：视频轨 / 人声 / BGM / 音效 / 字幕 / 花字 / 片头片尾；
- 一键「套包装」：选模板 → 自动加片头片尾、转场、花字、音效、调色、响度标准化；
- 预览（浏览器内 HLS/MP4）→ 导出 MP4 1080P / 剪映草稿 / OTIO；
- 版本对比：v1/v2 成片对比，回滚。

### 5.3 全局能力
- **任务中心**：所有生成/合成/导出任务，按项目过滤，失败重试；
- **费用**：按项目/集/供应商统计，预算告警；
- **设置**：ComfyUI 地址与工作流模板、LLM/TTS 供应商、存储、字体/音效库、团队权限（后期）。

## 7. 节目模式 DSL（本方案核心之一）

用 JSON/YAML 描述「一期节目怎么排」，平台解析后驱动台本生成、分镜模板、包装规则。

```yaml
id: roundtable_6min
name: 横屏 AI 圆桌 · 6 分钟
aspect: "16:9"
target_duration: 360
segments:
  - id: cold_open
    name: 冷开场
    duration: 15
    shots: [ { type: title_card, text: "{{topic}}", sfx: whoosh } ]
  - id: intro
    name: 开场+嘉宾介绍
    duration: 60
    pattern: host_to_camera + guest_intro_cards
    lower_thirds: true
  - id: topic_1
    name: 话题一
    duration: 120
    pattern: host_guest_shot_reverse + reaction_cutaway + b_roll
    pacing: medium
  - id: topic_2
    name: 话题二/小游戏
    duration: 120
    pattern: group_shot + reaction_cutaway + meme_card
    pacing: fast
  - id: closing
    name: 结尾+预告
    duration: 45
    pattern: host_to_camera + end_card
    sfx: outro_sting
packaging:
  intro: 5s_logo_sting
  outro: 8s_end_card
  lower_third_style: variety_yellow
  transition: cut + occasional_whip
  bgm: talk_show_light
```

配套的**镜头模板库**（shot pattern）：
| 模板 | 用途 | 生成方式 | 备注 |
|---|---|---|---|
| host_to_camera | 主持人口播 | H3 I2V（定妆照首帧） | 固定机位，5s |
| guest_intro_card | 嘉宾介绍 | 静帧 + 花字 + 轻推拉 | 不用生成视频，省成本 |
| shot_reverse | 正反打对话 | 两角色各生成 5s，交替剪辑 | 台词由 TTS 驱动 |
| reaction_cutaway | 反应镜头 | 1–2s 短生成或静帧抖动 | 综艺节奏关键 |
| b_roll / 空镜 | 环境/道具 | 静帧 + Ken Burns | 便宜，遮挡口型 |
| title/meme_card | 花字卡/梗图 | 模板渲染（Pillow/Canvas） | 无需生成 |

## 8. 生成链路（ComfyUI + MiniMax H3）

### 8.1 接入方式
1. 在 ComfyUI 里把已验证的 H3 工作流用 **「Save (API Format)」** 导出为 JSON；
2. 平台侧建「工作流模板」，声明参数映射（占位符）：

| 模板参数 | 映射到工作流节点 | 说明 |
|---|---|---|
| prompt | 正向提示词节点 | 镜头描述 |
| negative | 负向提示词节点 | 统一负面词 |
| seed | 采样器 seed | 固定可复现 |
| width/height | 空 latent / 图像尺寸 | 1280×720 |
| length/frames | 视频长度节点 | 5s / 8s / 10s |
| first_frame | Load Image → I2V 首帧 | 角色定妆照/分镜图 |
| ref_images | 参考图输入 | 角色一致性 |
| output | 保存节点 | 平台下载 |

3. 平台通过 HTTP 提交：`POST {COMFYUI}/prompt`，用 `/history/{prompt_id}` 或 WebSocket 监听完成，再 `GET /view?...` 拉回视频存 MinIO；
4. 队列：平台侧控制并发（建议 1–2），失败自动重试（≤2 次），超时 15 分钟；
5. provider 抽象：`ComfyUIProvider` / `CloudVideoProvider` 同一接口，后续可切即梦/可灵/Seedance。

### 8.2 生成策略（省钱 + 稳）
- **默认 5s/镜头**，长镜头最多 10s；总镜头数 70–100；
- **能静帧就不生成视频**：嘉宾介绍卡、花字卡、空镜、部分反应镜头用「静帧 + FFmpeg 推拉/抖动」；
- **对话用正反打**：A 说、B 反应，交替剪辑，规避多人同框；
- **首帧锁定**：每个说话镜头用角色定妆照 + 场景图合成首帧，再 I2V，保证不换脸；
- **固定 seed + 统一 LUT**：同场景镜头统一色调；
- **生成顺序**：先跑「说话镜头」和「关键反应镜头」，空镜/花字最后补。

### 8.3 P0 必须先验证的 H3 事项（清单）
- [ ] H3 在 ComfyUI 里的实际接入方式（本地权重 / API 节点 / 中转服务）；
- [ ] 单次生成时长上限、分辨率档位（确认 1280×720 可用）、是否支持首帧/参考图；
- [ ] 5s 片段平均耗时、失败率、并发限制；
- [ ] 是否原生带音频（音画同步）；若带，能否指定台词/音色；
- [ ] 商用条款与内容政策（H3 提供方/中转方）；
- [ ] 是否支持固定 seed/角色参考（决定一致性方案）。

> 结论先按「H3 只出画面、音频全后期」设计；若 H3 原生音频可用，再作为增强项接入。

## 9. 音频、字幕、口型

### 9.1 配音（TTS）
- 供应商：MiniMax Speech / 火山 / 阿里 CosyVoice（API），或本地 IndexTTS（需 GPU，暂不优先）；
- 每个角色绑定固定音色 + 语速 + 情绪参数；
- 台本按「说话人」分段合成，输出带时间戳的音频（无时间戳则用 whisper.cpp 在 CPU 上强制对齐）；
- 支持「口头禅/语气词」插入，增加综艺感。

### 9.2 字幕
- 用 TTS 时间戳或 ASR 对齐生成 SRT/ASS；
- 字幕样式模板（字体、描边、位置、双行），与花字风格统一；
- 默认硬字幕烧录；同时导出软字幕文件。

### 9.3 口型（MVP 策略：规避优先）
- 横屏中景 + 正反打 + 反应镜头 + 花字遮挡，**允许口型不完美**；
- 单人特写如必须精修，接云端口型服务或后期 LatentSync（需要 GPU，可作为 P3 可选增强）；
- 若 H3 原生音画同步可用，优先用 H3 生成带对白的镜头（需实测台词可控性）。

## 10. 包装引擎（综艺感的关键）

| 模块 | 内容 | 实现 |
|---|---|---|
| 片头 | 5–8s logo 动画 + 音效 + 字幕 | 模板视频 + FFmpeg overlay；或 AE 预渲染模板 |
| 片尾 | 8–10s 结束卡 + 下期预告 + 关注引导 | 模板渲染 |
| 花字 | 下三分之一、强调字、梗图、标签 | ASS 字幕模板 / Pillow 渲染 PNG → overlay |
| 转场 | 硬切为主 + 少量 whoosh 转场 | FFmpeg xfade（10+ 预设） |
| 音效 | 转场 whoosh、强调 ding、笑声/掌声、打字声 | 免费商用音效库 + 映射表 |
| BGM | 轻综艺/谈话类 BGM，自动 ducking | 版权库（先建 10 首白名单） |
| 调色 | 统一 LUT、肤色保护 | FFmpeg lut3d + 轻度锐化 |
| 混音 | 人声 -16 LUFS、BGM -25、SFX -20，loudnorm | FFmpeg loudnorm |
| 封面/标题 | 自动生成封面图 + 标题文案 | 模板渲染 |

**模板化原则**：每个模板 = 一个目录（视频/ASS/音频/配置），平台只认接口，不写死样式。

## 11. 合成与导出

### 11.1 合成流水线（FFmpeg worker）
1. 按时间线 concat 视频轨（含转场）；
2. 叠加字幕/花字（ASS）；
3. 混音：人声 + BGM（ducking）+ 音效；
4. 片头片尾拼接；
5. 调色 + 锐化 + 响度标准化；
6. 输出 H.264/H.265 1080P，码率 8–12 Mbps；可选 720P 预览版。

### 11.2 导出格式
- **MP4 1080P**（主交付）；
- **剪映草稿**（可选，给后期精修；参考 ArcReel 的导出方式，自己实现草稿 JSON）；
- **OTIO**（OpenTimelineIO）作为中间时间线，方便以后接 PR/达芬奇/FCPXML；
- 素材清单 + 字幕文件 + 封面图。

### 11.3 目录约定
```
projects/{project_id}/episodes/{episode_no}/
  script.json  assets/  shots/  outputs/  timeline/v{n}.json
  renders/v{n}/final.mp4  renders/v{n}/cover.jpg  renders/v{n}/subtitles.ass
```

## 12. 质检与一致性

| 检查 | 方法 | 失败动作 |
|---|---|---|
| 黑帧/静帧异常 | FFmpeg blackdetect/freeze detect | 标记重生成 |
| 静音/爆音 | FFmpeg volumedetect | 重配/调音量 |
| 时长/分辨率/帧率 | ffprobe | 自动修正或重导 |
| 口型 | 抽帧 + 人工/模型抽检 | 换镜头或切镜规避 |
| 角色一致性 | 人脸 embedding 相似度（CPU 可用）+ 人工 | 换参考图/重生成 |
| 字幕错字 | 台本对照（字幕由台本生成，天然一致） | — |
| 合规 | AI 标识水印、敏感词、肖像/声音清单 | 阻断导出 |

**一致性三层保障**：资产锁定（定妆照/参考图）→ 首帧锁定（每镜头首帧）→ 统一调色/风格 LUT。

## 13. 成本与产能模型

### 13.1 单集（6–8 分钟，横屏 768P）估算
| 项 | 用量 | 单价 | 小计 |
|---|---|---|---|
| H3 视频生成 | 80–120 镜头 × 5s = 400–600s；含 30% 重试 ≈ 520–780s | ¥0.08–0.09/秒（行情） | **¥42–70** |
| 静帧/空镜/花字 | 不生成视频 | — | ¥0 |
| TTS | 3,000–6,000 字 | ¥0.1–1/千字 | ¥1–6 |
| LLM（台本/分镜/prompt） | 若干次 | — | ¥2–10 |
| 存储/带宽 | 几 GB | — | < ¥1 |
| **合计（现金）** | | | **¥50–90/集** |
| 人力（质检/微调） | 0.5–2 人天 | — | 主要成本 |

> 对比：全云 1080P 视频生成（约 ¥1.5/秒）跑 6 分钟 ≈ ¥540/集。**768P + 静帧混合是成本优势的核心。**

### 13.2 时间
- 生成：80–120 个任务，按 1–2 并发、每任务 1–3 分钟 → **2–5 小时/集**（可夜间跑）；
- 合成/包装：5–15 分钟/集；
- 人工：台本审校 1–2 小时、镜头抽检/替换 2–6 小时、成片审看 0.5 小时。

### 13.3 产能目标（v0.1）
- 单条产线：**1 人 2–3 天/集**；
- 稳定后：**1 人 1–1.5 天/集**，每周 2–3 集。

## 17. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| H3 可用性/限流/中断 | 卡生产 | provider 可切换（云视频 API 兜底）；队列重试；离线素材缓存 |

| ArcReel AGPL | 法律风险 | 只借鉴交互逻辑与信息架构，不复制代码；自研实现 |
| 模式单一 | 内容同质化 | 先固化 1 个模式跑通，再按月加模式 |

## 附录 B：H3 工作流模板约定（ComfyUI API JSON）

- 每个模板 JSON 带 `_meta`：`template_id / description / supported_params`；
- 平台只允许改白名单参数（prompt/negative/seed/width/height/length/first_frame/ref_images）；
- 输出节点必须固定命名（如 `SaveVideo`），平台按节点名取结果；
- 模板版本化，工作流更新不影响历史任务复现。
